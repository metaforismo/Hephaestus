# Registered matched tiles

The combinational constant-matrix cores now have a matched synchronous boundary suitable for the
next physical-design experiments. This layer does not alter coefficient topology. It places the
same input register, output register, valid pipeline, reset behavior, and bus contract around each
of the three already matched backends.

```text
verified integer contract
  → matched combinational RTL
  → exhaustive Yosys-SAT proof of all three source cores
  → identical registered streaming wrappers
  → independent Python arithmetic oracle
  → continuous traffic plus valid bubbles
  → data-dependent simulation negative control
```

## Interface contract

Every wrapper exposes:

```text
clk
reset
valid_in
x_flat
valid_out
y_flat
```

The contract is:

```text
clock edge:             rising
reset:                  synchronous, active high
input registration:     yes
output registration:    yes
valid latency:          1 cycle
value latency:          1 cycle
initiation interval:    1 cycle
runtime weight reads:   0 per matrix-vector operation
```

A value presented with `valid_in = 1` at edge `N` is returned with `valid_out = 1` at edge `N + 1`.
The wrapper can accept another value on every edge. A cycle with `valid_in = 0` creates one matching
bubble at the output without changing the latency of surrounding transactions.

## Source binding

`python -m hephaestus.registered` refuses to wrap an arbitrary RTL file. It requires:

- a verified `hephaestus.matched-baselines.v1` bundle;
- the exact `codes.npy` digest named by that bundle;
- `hephaestus.formal-equivalence-evidence.v1` for the same manifest and code matrix;
- successful exhaustive combinational proofs for all three backends;
- a formal negative control that produces a counterexample;
- exact SHA-256 matches for every source RTL file;
- zero runtime coefficient reads in each source backend.

The registered evidence manifest preserves copies and digests of the matched manifest, code matrix,
formal evidence, source cores, wrappers, independent reference core, verification oracle,
testbenches, and simulation logs.

## Artifact bundle

A successful build writes a self-contained directory such as:

```text
build/registered/tiles/
├── registered_manifest.json
├── verification_oracle.json
├── source_matched_manifest.json
├── source_formal_evidence.json
├── source_codes.npy
├── shared_dag_core.sv
├── shared_dag_registered.sv
├── naive_shift_add_core.sv
├── naive_shift_add_registered.sv
├── constant_multipliers_core.sv
├── constant_multipliers_registered.sv
├── reference_core.sv
├── registered_testbench.sv
├── negative_control_registered.sv
├── negative_control_testbench.sv
└── positive.* / negative_control.* simulation logs
```

`registered_manifest.json` is the authority for the generated interface, source bindings, artifact
digests, verification schedule, and claim boundary. The manifest deliberately keeps schedule-based
claims false when the builder is run without `--simulate`; generating RTL alone is not treated as a
verified registered implementation.

## Pinned regression

The regression authority is:

```text
benchmarks/reference/registered_matched_tiles_tiny_v1.json
```

For `examples/tiny_weights.json`, seed 59, and 256 requested random vectors, the deduplicated
schedule contains:

```text
valid vectors:   272
bubble cycles:    39
schedule cycles: 311
```

The reference pins the 48-bit input/output contract, all three source-core digests, all three
wrapper digests, the independent reference core, arithmetic oracle, positive testbench, and both
negative-control artifacts. CI regenerates those files and refuses a byte-level regression in any
of the pinned artifacts.

The qualifying run was workflow `32168999063` on head
`5a839915ad873c234f93b61030e438f683550360`. Its uploaded ZIP has SHA-256:

```text
2527c95a904598d10526b1740b1110db788ccf2fffeb7674e03eca0456834e8a
```

The positive simulation reported all 272 vectors passing. The negative control flipped one output
bit only when a valid transaction carried a selected data bit and was rejected with a concrete
oracle mismatch. Run IDs and ZIP digests document the qualifying observation; the permanent
regression is the checked-in reference plus regenerated artifact digests.

## Verification method

The streaming testbench does not compare the wrappers only against another wrapper generated by the
same function. Python evaluates the code matrix directly for deterministic signed corner cases,
one-lane extrema, and seeded random packed inputs. Those expected outputs are embedded in a
versioned oracle artifact and checked after exactly one cycle.

The schedule combines consecutive valid transactions with deterministic bubbles. It checks:

- output data against the independent arithmetic oracle;
- one-cycle `valid` alignment;
- acceptance of a new value every cycle;
- propagation of bubbles;
- synchronous reset clearing both valid and output state.

A second testbench replaces only the shared-DAG wrapper with a data-dependent one-bit output fault.
The evidence build must observe that failure, otherwise the simulation harness is rejected.

## Reproduction

```bash
python -m hephaestus compile examples/tiny_weights.json \
  --out build/registered/source \
  --module hephaestus_registered_source \
  --verify-samples 256

python -m hephaestus.baselines build/registered/source \
  --out build/registered/matched \
  --module hephaestus_registered \
  --verify-vectors 256 \
  --seed 59 \
  --simulate

python -m hephaestus.formal build/registered/matched \
  --codes build/registered/source/codes.npy \
  --out build/registered/formal \
  --max-input-bits 64

python -m hephaestus.registered build/registered/matched \
  --codes build/registered/source/codes.npy \
  --formal-evidence build/registered/formal/formal_evidence.json \
  --out build/registered/tiles \
  --module hephaestus_registered_tile \
  --verify-vectors 256 \
  --seed 59 \
  --simulate
```

The permanent CI flow is `.github/workflows/registered-tiles.yml`.

## Claim boundary

A passing bundle may claim that:

- the wrappers were generated around source cores already proved exhaustively combinationally;
- all three wrappers matched an independent arithmetic oracle on the executed streaming schedule;
- one-cycle latency, initiation interval one, reset clearing, and valid bubbles were exercised;
- the simulation negative control detected its injected data-dependent fault.

It does not yet claim:

- unbounded sequential formal equivalence;
- a closed product clock frequency;
- mapped sequential PPA;
- placement, routing, congestion, extracted RC, or activity-based power;
- DRC, LVS, PEX, foundry sign-off, or fabricated silicon.

The next evidence layer consumes these wrappers in one pinned IHP SG13G2 OpenROAD flow with matched
floorplan, clock, utilization, placement, routing, and extraction constraints.
